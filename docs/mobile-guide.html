First launch

On first launch the app will ask you to set a password. It protects access to the app and encrypts the conversation history and connection data.

Password must be at least 4 characters. After 5 failed attempts all data will be deleted.

After setting the password, a PIN entry screen will appear on every launch. Auto-lock after a configured period of inactivity — configurable in the Security section.

Main screen

The main screen consists of several zones:

  • Header — app name and current session
  • 🎤 / 👆 — quick toggle for VAD: 🎤 voice mode (VAD), 👆 manual mode
  • 🔊 / 🔇 — quick toggle for response text-to-speech
  • ⚙️ — settings button in the top-right corner; current time is displayed below it
  • 🟢 / 🟠 / 🔴 indicator next to the gear — server status:
    🟢 available, 🟠 server version outdated (update needed), 🔴 unavailable
  • Message feed — conversation history with Claude, persisted between app restarts
  • ▼ Terminal — expand the Claude session screen panel
  • Input field — type messages manually + ↑ button to send
  • Tap to speak — voice input button

Settings

Settings are opened with the ⚙️ button in the top-right corner. Divided into five sections:

  • General — request locking, haptic feedback and hang timeout, font size, terminal height, working directory
  • Audio — hands-free voice input (VAD), text-to-speech, haptic
  • Security — auto-lock timer and password change
  • Connection — server address, API keys
  • Language — language for speech recognition and response synthesis

Settings — General

Request locking

Enabled by default. In this mode, requests to a single session are processed strictly one at a time — the next request waits until the previous one receives a response.

Multi-user mode. The app allows multiple users to connect to the same Claude session simultaneously — from different phones. The lock prevents conflicts: if one user has already sent a request, the second user's request will be queued and processed after the response is received. Without the lock, both requests would enter the session at the same time, which can lead to unpredictable behavior.

Single-user mode. If you work alone — the lock can be disabled. This lets you send a new request without waiting for a response to the previous one, for example in parallel with working in the terminal on your computer. On login and when switching sessions the app will remind you that the lock is disabled.

Haptic on hang

Haptic feedback when a session hangs: Off / Light / Medium / Heavy.

Hang timeout (sec)

Time in seconds without changes on the terminal screen, after which the session is considered hung. Default is 20 seconds.

Font size

Font size for chat messages and terminal text. Range 8–40, default 15. Useful to increase if the screen is small or you need larger text.

Terminal lines

Height of the terminal panel in lines. The actual height is limited by the screen size — the panel will not exceed screen bounds even if you set a large value.

Projects directory

Base folder for new sessions on the server, e.g. /home/user/projects. The working directory of a new session must be inside it or in one of its subdirectories. Required for creating new sessions.

Settings — Audio

Text-to-speech

Enable or disable reading Claude's responses aloud. Also available as a quick toggle with the 🔊/🔇 button in the main screen header.

Voice gender

Choose the voice for reading responses: ♀ female or ♂ male. Applies to all languages.

VAD

Hands-free voice input mode. Also available as a quick toggle with the 🎤/👆 button in the main screen header. More details in the VAD section.

Wake phrase

A word or phrase that starts recording. Choose something the STT reliably recognises in your voice.

End phrase

A word or phrase that ends recording and sends the message.

Haptic feedback

Haptic feedback at the start and end of recording in VAD mode: Off / Light / Medium / Heavy.

Settings — Security

Lock after (min)

Inactivity time in minutes after which the app locks and asks for the password. Value 0 — never lock automatically.

Activity is any screen touch, as well as sending and receiving messages — so in VAD mode the timer also resets with each exchange.

Change password

Change the password. You will need to enter the current password, then the new one twice. When the password is changed, all data is automatically re-encrypted with the new key.

Connection settings

Connection — server connection

Fill in the fields:

  • Server URL — server address (see options below)
  • Server API Key — secret server key (set during installation)
  • STT API Key — key for speech recognition (Groq or another provider). Optional if the key is already configured on the server.
Connection data is stored locally on the phone in encrypted form — the encryption key is derived from your password.

Server connection options

1. Home Wi-Fi
Phone and computer on the same network. Find the computer's IP and connect directly via HTTP (limited to network range).

2. Public IP + domain + trusted certificate
If you have a server with a public IP, you will need a domain name and a trusted certificate (if you don't have them yet — you can get them for free via DuckDNS and Let's Encrypt).

3. Public IP + self-signed certificate
Generate a certificate with the required IP in the SAN field, install it on the phone as a trusted CA and connect directly by IP without a domain.

4. Tailscale + HTTP
If you don't have a public IP — install Tailscale on the server and phone. Traffic goes through an encrypted WireGuard tunnel, so HTTP inside it is secure. No certificates needed.

Detailed connection description in the server documentation.

Settings — Language

Choose the language for speech recognition and response synthesis. The current language is shown in the section header.

Available languages: Chinese, English, French, German, Japanese, Russian, Spanish.

Voice input

Manual mode

By default the app works in manual mode. Full cycle of one request:

  • Tap 🎤 Tap to speak — recording will start
  • Speak — the button becomes 🔴 Speaking...
  • Tap again — the recording is sent, the button dims, speech recognition runs and your message appears in the feed
  • When Claude responds, its message appears and the button turns orange 🔊 Speaking... — text-to-speech is playing
  • At any moment the action can be cancelled by tapping ✕
  • Below Claude's response there is a ⎘ button — copy the text to clipboard
During processing or playback the ↑ button in the input field turns into ✕ — tap it to cancel the request.

VAD — hands-free voice input

In Audio settings enable the VAD toggle. The app will start continuously listening via the built-in STT and react to marker phrases — no button presses needed, hands are completely free.

How it works

  1. The app is always listening in the background, status — 👂 Say "..."
  2. Say the wake phrase — the phone will vibrate and a short beep will play. Status — Say "..." to send
  3. Speak your message — everything after the wake phrase is recorded
  4. Say the end phrase — the message between the markers is automatically sent to Claude. A completion beep plays
Wake and end phrases can be changed in Audio → Wake phrase and Audio → End phrase. Choose words that the STT reliably recognises in your voice and that don't appear in normal speech by accident. The wake and end phrases may be the same.
VAD uses online speech recognition and requires a stable internet connection. In poor connection conditions VAD may work incorrectly — use manual mode in such situations.

Use cases

VAD is convenient when your hands are busy or you can't look at the screen — while driving, on a walk, or working at a computer. Enable the mode, place the phone in front of you or put it in your pocket and use a headset.

Text input

At the bottom of the screen there is a text input field. Useful when you need to send precise data — code, a link, specific terms — that cannot be said by voice, or when voice control is not possible.

  • Tap the input field to start typing
  • Tap ↑ to send
  • The field supports multi-line input
  • The "Tap to speak" button hides when the keyboard is open
  • To dismiss the keyboard — tap the message feed

Terminal

Sometimes during operation Claude requires confirmation for its actions. In this case execution pauses and the session hangs. The app monitors the Claude session screen state and, if it does not change for longer than the configured interval (General → Hang timeout), the Terminal label turns red and the phone may vibrate (configured in General → Haptic on hang).

Tap ▼ Terminal to open the panel with the Claude session screen and see what is happening. The terminal loads up to 2000 lines of history and updates every 2 seconds. History can be scrolled with a finger.

Panel height and font size are configured in General → Terminal lines and General → Font size.

Available control keys:

  • Esc — cancel action
  • ⏬︎ — scroll terminal to bottom and enable auto-scroll
  • ↑ / ↓ — navigate menu
  • ↵ Enter — confirm selection
When Claude shows a menu with response options — use the arrows to select and Enter to confirm. Esc — to cancel.

Example: Claude is asking permission to perform an action. Three response options are visible. Select the one you need with the arrows and press Enter.

Claude session management

Tap the session name below the app header to open the session list.

Session list

  • 🟢 running — session is running in tmux
  • ⚪ stopped — session is stopped, will start when you switch to it
  • ▶ before the name — current active session

Tap a session to switch to it. The app remembers the last session and automatically restores it after a restart.

⏹ next to the active session — end the session: stops tmux and locks the app to the PIN screen.
↻ next to the active session — recreate with a fresh context.
✕ next to an inactive session — remove from the list.

A stopped session will start automatically when you send a message to it.
Removing a session from the list does not delete files in the project directory.

Creating a new session

Creating a new session requires the Projects directory field to be filled in under Connection settings. The working directory of the new session must be inside Projects directory or one of its subdirectories.

Expand the New session section:

  • Enter a session name — the path will be filled in automatically based on the Projects directory from settings
  • If needed, edit the path manually
  • Enable Use template: conversation + lab to create two sessions at once — name-discussion and name-lab in separate folders with a ready-made CLAUDE.md
  • Tap + Create

The discussion + lab template

Splits project work into two specialized sessions:

  • discussion — a session for discussing, planning and making decisions. Does not write code.
  • lab — a working session that implements what was decided in discussion.

Each session gets its own CLAUDE.md with role instructions. Shared project files STATUS.md and CONTEXT.md are created in the root of the project folder and are accessible to both sessions.

The split reduces the context load on each session and helps Claude stay in its role — not getting distracted by implementation details during discussion or by philosophy when writing code.

Shell session management

Shell sessions provide terminal access to the server. These are regular tmux sessions on the server, independent of Claude Code — you can run any commands, view logs, restart services. Terminal history can be scrolled with a finger.

Opening a Shell session

Tap the current Claude session name in the header to open the menu. The Shell sessions section shows the list of existing tmux sessions on the server. Tap a session — it will open by swiping right from the main screen.

To return to the main screen — swipe left. To close the Shell page, tap ✕ in the top-right corner — the session on the server continues running.

Open Shell sessions are saved between app restarts — after login they will be available immediately.

Creating a new Shell session

Expand New Shell session in the menu, enter a name and tap + Create. The new session starts in the directory from General → Projects directory settings. If the directory does not exist — the session starts from the user's home directory.

Deleting a Shell session

In the Shell sessions menu tap ✕ next to the session. A confirmation dialog will appear — after confirming, the tmux session will be terminated on the server.

Terminal input

  • Tap ⌨️ to open the keyboard.
  • Everything you type goes directly to the terminal — character by character.
  • Paste from clipboard: use Ctrl + V via sticky modifiers.

Copying from the terminal

Long-press text on the terminal screen to select and copy it.

Special keys

Above the keyboard button there is a row of special keys. The row scrolls horizontally.

Sticky modifiers: Ctrl, Alt, Shift

Tap a modifier — it highlights in blue and stays pressed. Then tap a key on the keyboard — the combination is sent to the terminal and the modifier turns off.

  • Ctrl + C — interrupt a running process
  • Ctrl + D — end session / exit bash
  • Ctrl + Z — suspend a process
  • Ctrl + V — paste from clipboard
  • Shift + digit — enter a special character ($, !, @, #, etc.)

Navigation keys

  • ↓ / ↑ — navigate command history
  • ← / → — move cursor within the line
  • ↵ — Enter
  • ⏬︎ — scroll terminal to bottom and enable auto-scroll
  • Tab — autocomplete path or command. Press twice to show all options.

The key row scrolls horizontally — including when the keyboard is closed.

The current cursor position in the terminal is shown with a blue character highlight.

If you scroll the terminal up, auto-scroll is disabled — new lines won't jump to the bottom. Press ⏬︎ to return to the end and re-enable auto-scroll.

Updates

On launch the app checks for a new version on GitHub. If a newer version is available — a button «vX.X.X available — tap to download» appears on the login screen. Tap it to open the releases page in the browser.

When updating the mobile app, also check the server version: if the indicator next to the gear turned orange 🟠 — the server needs to be updated. Download the source archive from the same GitHub release (Source code), update the server files and restart the service.

Data encryption

All sensitive data is stored locally on the phone in encrypted form. The encryption key is never saved anywhere — it is derived from the password on every login and exists only in memory.

What is encrypted

  • Connection data — server address, Server API Key, STT API Key
  • Conversation history — all messages in the dialogue with Claude
  • Current Claude session name — restored after app restart
  • Open Shell session names — list of sessions restored after app restart

Technical details

  • When a password is created, a random salt (128 bits) is generated
  • A 256-bit encryption key is derived from the password and salt via PBKDF2-SHA256 (1000 iterations)
  • A separate PBKDF2-SHA512 hash (1000 iterations) is used to verify the password on login — the key itself is not stored
  • Data is encrypted with the AES-256 algorithm
  • When the password is changed, all data is automatically re-encrypted with the new key
After 5 failed password attempts all encrypted data is deleted from the device. After that you will need to set a new password and reconnect to the server. Deleting data on the device does not affect the integrity of data on the server.

Building APK from source

You will need Node.js 18+, Android SDK and Java 17. The build runs locally without cloud services.

Quick build with the script

The claude-wheel-mobile folder contains a script build-apk.sh that automates the entire process:

cd claude-wheel-mobile
bash build-apk.sh

The script performs:

  1. Syncing sources to the build folder ~/builds/claude-wheel-mobile/
  2. Installing dependencies (npm install)
  3. expo prebuild on first run or when app.json changes
  4. Build via Gradle (assembleRelease, arm64 only)
  5. Copying the finished APK to ~/builds/claude-wheel.apk

Tips

  • If the server is temporarily unavailable, the indicator turns red. The app checks the connection on its own and will update the status when the server responds again.
  • To copy Claude's response — tap the ⎘ icon below the message.
  • If the Terminal button turned red during processing — the session is not responding. Open the terminal and see what is happening.
  • If you started a voice message in manual mode but changed your mind about sending it — stop the recording and immediately tap ✕ to cancel the send.
  • In VAD mode, if recording has started but you don't want to send — tap ✕ next to the recording indicator. The recording will be discarded and VAD will return to listening.
  • If you don't want to listen to the full response — tap ✕ to stop playback.
  • If you want to delete all app data from the phone, enter the wrong PIN 5 times in a row.
